# Отчёт: Умный поиск IT-вакансий

## 1. Задача и данные

**Задача:** по профилю кандидата (навыки, опыт, зарплата) найти подходящие
IT-вакансии, оценить совпадение и указать пробелы в навыках.

**Источник данных:** датасет [IT vacancies from hh.ru](https://huggingface.co/datasets/trewwxsav/IT_vacancies_from_hh.ru)
на HuggingFace — 68 584 реальных IT-вакансий, собранных с hh.ru через публичный API.
Формат: CSV (cp1251, `;`), 7 колонок: название, компания, опыт, город, требования,
зарплата. Загружаем 100 вакансий для эксперимента (`scraper.py`).

**Подготовка:**
1. `scraper.py` → `input/vacancies.json` (100 вакансий, raw)
2. `extractor.py` → `output/extracted_vacancies.json` (100 вакансий, Pydantic-объекты,
   извлечение навыков через LLM из полных описаний `требования_обязанности`)

## 2. Система

### Схема пути данных

```
HuggingFace dataset (hh.ru, 68 584 вакансий)
    ↓ scraper.py
input/vacancies.json (raw JSON)
    ↓ extractor.py  [structured output + field_validator]
output/extracted_vacancies.json (list[Vacancy])
    ↓
    ├─ rag.py         [BM25 + LLM answer gen]
    ├─ hallucination.py [LLM-as-judge: ghost-skills]
    └─ agent.py       [Planner → Workers → Critic]
         ↓ eval.py    [LLM-as-judge: 15 кейсов]
output/eval_results.json
```

### Техника 1: Structured output + `@field_validator`

`schemas.py` — четыре ключевых валидатора:

```python
@field_validator("salary_max")
def max_not_less_than_min(cls, v, info):
    if v is not None and info.data.get("salary_min") is not None:
        if v < info.data["salary_min"]:
            raise ValueError(f"salary_max ({v}) < salary_min")
    return v

@field_validator("experience_years")
def experience_non_negative(cls, v):
    if v < 0:
        raise ValueError("experience_years must be >= 0")
    return v

# HallucinationReport:
@field_validator("hallucination_rate")
def rate_in_range(cls, v):
    if not 0.0 <= v <= 1.0:
        raise ValueError(f"hallucination_rate {v} not in [0, 1]")
    return v

# MatchResult:
score: int = Field(ge=1, le=10)
```

В `extractor.py`: LLM вызывается с `response_model=Vacancy, max_retries=2`.
При 3 пустых ответах от модели — fallback на базовые поля из raw-данных (без LLM).

### Техника 3: LLM-as-judge

Используется в двух местах:
- **`hallucination.py`** — проверяет, есть ли каждый extracted skill в тексте
  описания (`temperature=0.7`, `SkillVerification(skill, present_in_text, evidence)`)
- **`eval.py`** — оценивает качество финального ответа агента (score 1–10,
  pass = score ≥ 7)

### Техника 4: Агент с инструментами

`agent.py` — три tools:

| Tool | Описание |
|------|----------|
| `search_vacancies(query, top_k)` | BM25-поиск по корпусу |
| `score_match(profile, vacancy_id)` | LLM оценивает совпадение 1-10 |
| `get_skills_gap(profile, vacancy_ids)` | множественная разность навыков |

### Техника 5: Мультиагент (PWC)

`agent.py` — Planner → Workers (параллельно через ThreadPoolExecutor) → Critic:
- **Planner**: прошитый план из 3 шагов (search → score → gap)
- **Workers**: шаги 2 и 3 независимы, выполняются параллельно
- **Critic**: `AgentVerdict(ok, score, reasoning)`, `temperature=0.7`, pass = score ≥ 7

34.9% ghost-rate на реальных hh.ru-описаниях объясним несколькими причинами:
- LLM-экстрактор выводит навыки из контекста (например, "работаем на React" → `React`, `JavaScript`), а судья требует дословного присутствия
- Встроенные описания (`инженер-программист`) содержат навыки в аббревиатурах/контексте (RTOS → embedded), которые судья не засчитывает
- Некоторые позиции (`senior node.js developer`, 88% ghost) имеют очень краткие описания — скиллы вообще отсутствуют явно

Это показывает, что `hallucination.py` действительно ловит реальное расхождение между extracted_skills и текстом вакансии, а не тривиально возвращает 0%.

## 4. Где ошибался

### Ошибка 1: BM25 возвращает дублирующиеся вакансии (случаи 7 и 10)

Датасет содержит дубли — одна и та же вакансия (Middle Python Developer, Kesmaty)
встречается 5+ раз с разными ID. BM25 находит топ-3, и все три — один и тот же
работодатель. Агент сообщает три одинаковых позиции → judge ставит 5/10.
**Что исправить:** дедупликация корпуса по паре `(title, company)` перед индексацией.

### Ошибка 2: RAG не видит зарплату и даёт пустой ответ (случаи 12, 15)

BM25 ищет по тексту, но зарплата — числовое поле, его нет в тексте описания.
«Вакансии >200к для ML-инженера» → BM25 игнорирует числовой фильтр → ответ «нет вакансий».
**Что исправить:** гибридный поиск BM25 + структурный фильтр по полям salary_min/max.

### Ошибка 3: LLM возвращает пустой JSON при extraction и eval (случай 2)

8 вакансий при extraction, 1 при eval получили пустой ответ (`''`). Fallback в extractor
спасает, но в eval agent получает ошибку и не возвращает ответ → score=0, fail.
**Что исправить:** retry с другим промптом при пустом ответе + timeout guard в agent.

### Ошибка 4: Высокий ghost-rate (34.9%) из-за строгого судьи

LLM-as-judge требует дословного присутствия навыка. Но экстрактор делает выводы
из контекста: «we use React» → `['React', 'JavaScript']`. JavaScript отсутствует
дословно → ghost. Это не ошибка системы, а разница в определении «галлюцинации».
**Что исправить:** ввести нечёткую проверку — навык считается present если есть
смысловое пересечение, не только строгое совпадение.

## 5. Выводы

**Что работает хорошо:**
- Structured output с field_validator: поймал несоответствия salary_max < salary_min
  и отрицательный experience при обработке реальных данных hh.ru
- LLM-as-judge как оценщик качества ответа: score хорошо коррелирует с тем,
  насколько ответ полезен кандидату
- Hallucination check: 34.9% ghost-rate на реальных данных подтвердил, что
  LLM-экстрактор действительно выводит навыки из контекста — не просто копирует

**Что слабее:**
- Agent mode: 73% pass (не 100%) — реальный датасет разнородный (PHP, Node.js,
  Solidity), ML-запросы попадают в нерелевантные вакансии
- RAG: 25% pass — BM25 не умеет фильтровать по числовым полям (зарплата)
  и не знает о дублях в корпусе
- Дубликаты в датасете: 5+ копий одной вакансии искажают top-K результаты

**В продакшн:** дедупликация корпуса + гибридный поиск (BM25 + структурный фильтр),
увеличить корпус до 500+ вакансий только IT/ML специализаций, добавить retry-логику
в agent при пустом LLM-ответе.
